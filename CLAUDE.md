# Dota 2 Meta — контекст проекта

Сайт на GitHub Pages (`main`, корень): https://istrebitelmefa.github.io/Dota2-meta/
Пользователь общается по-русски, интерфейс сайта тоже на русском.

**Деплой после каждого изменения:** пользователь проверяет сайт с телефона, поэтому после каждой правки коммить и пушь сразу в `main` (GitHub Pages собирается ~1–2 мин) и присылай ссылку вида `https://istrebitelmefa.github.io/Dota2-meta/?v=<короткий хэш коммита>` (параметр обходит кэш браузера).

## Что делает сайт
Один файл `index.html` (vanilla JS, без сборки). Вкладки:
- **Позиции 1–5** (одна логика в SQL `posCTE()` и в JS `positions()`): саппорты — двое в команде с наименьшими добиваниями к 10-й минуте (`lh_t[11]` в SQL / `lh_t[10]` в JS; без парсинга — итоговые `last_hits`); из них 5 — на лёгкой линии (`lane_role=1`), 4 — на сложной/в роуме, при равенстве 5 — с меньшим GPM. Коры по `lane_role`: 1→1, 2→2, 3→3, спорные — по фарму. НЕ определять позиции по итоговому GPM — путается.
- **Связки** — переключатель «Пары»: керри (1) + 5 или 4 + 5, обе через `posCTE()`; 4 + 5 грузится лениво (`S.duos45`).
  Винрейт, W–L, число игр, «синергия» (WR пары минус средний WR героев), сортировка по нижней границе Уилсона.
- **Сборки** — по `purchase_log` (стартовые, ранние, лучшая сборка по времени покупки, ситуативные, таблица всех предметов, лучшие напарники). Фолбэк — итоговый инвентарь `item_0..5`.
- **Варды** — карта `map_740.webp` (из odota/web, карта 7.40) с позициями из `obs_log`/`sen_log` последних 2000 про-матчей периода. Координаты 64..191 → `u=(x-64)/127, v=(191-y)/127` (как у OpenDota). Соседние клетки жадно кластеризуются в «центряки» (средневзвешенный центр), фильтры: тип варда (обсы/сентри/оба — по умолчанию оба), сторона, время, число точек, тепловая карта. Точки: маленькие жёлтые (obs) и синие (sen) с номером места в топе.
- **Разбор матча** — ввод номера/ссылки матча или Steam/Friend ID (→ `/players/{id}/recentMatches`). Матч из `/matches/{id}`; если не распарсен (нет `gold_t`) — кнопка `POST /request/{id}` и опрос. Позиции — `positions()` (см. выше). Эвристики: смерти (из `kills_log` врагов) vs средние про по позиции (SQL `fetchPosAvg`), линия на 10-й минуте (gold_t+xp_t своих vs врагов на той же `lane`), `benchmarks`, `teamfight_participation`, тайминги предметов vs про на герое (`heroItemRows`), ТП; для 4/5 — число obs/sen vs про, время жизни obs (`obs_left_log` по `ehandle`), доля вардов в топ-30 метовых точках, стаки. Карта вардов игрока.
  Режим «Кто тащил / кто руинил» (`renderRanking`/`ratePlayer`): оценка 0–10 всех 10 игроков = взвешенные компоненты в [-1;1]: процентили `benchmarks` (набор зависит от позиции), смерти vs норма позиции, участие в убийствах, линия к 10 мин (только распарсенные), обсы для 4/5. Значки MVP / Тащил / Руинил / N ошибок.
- **Игрок** — по Steam/Friend ID (`#player=<id>` в адресе открывает сразу). Эндпоинты `/players/{id}` + `/wl`, `/heroes`, `/peers`, `/totals`, `/counts`, `/matches?limit=300&project=…`, `/wardmap` с фильтрами `date`, `lobby_type=7`. Выводы: форма (скользящий винрейт, SVG + HTML-подписи), сильные/слабые герои (Уилсон), ширина пула, линии, сторона, длительность, соло/пати, время суток, тильт после поражения и усталость (сессия = перерыв < 1,5 ч), варды игрока vs топ-40 метовых точек. Из «Разбора матча» — кнопка «Статистика игрока».
- **Изменения патча** — `/constants/patchnotes` (все патчи, ~3 МБ; ключи `7_42`, `7_41f`; внутри `general` — строки, `items` — {item: [строки]}, `heroes` — {hero: {ability_key|general|talents: [строки]}}, `heroes.misc` — массив про нейтралки/крипов) и `/constants/abilities` (~2 МБ, для `dname`). Грузятся по требованию в память (`PN`, `loadNotes()`), НЕ в localStorage (не влезут). Строки содержат `<span class=\"Subtitle\">` и `<br>` — рендерит `noteLine()`. В «Сборках» — блок изменений героя в последнем крупном патче; в «Героях патча» — пометка «изм.». Текст на английском.
- **Герои патча** — пик/винрейт в про-матчах + паб-винрейт (ранги 7–8 из `/api/heroStats`).

## Данные
- Всё грузится в браузере из OpenDota API (`https://api.opendota.com/api/`), CORS открыт.
- Патчи: `/constants/patch` (без кэша). Селектор «Патч» — последние 4; выбранный патч = окно `[S.start; S.end)` (конец — выход следующего), во всех SQL `start_time BETWEEN ${st} AND ${periodEnd()}`. Если на новейшем патче < 400 про-матчей — автоматически показывается прошлый с плашкой «Показать новый всё равно» (выбор запоминается в `dm_patch_pick`).
- OpenDota добавляет новый патч в `/constants/patch` с задержкой (источник — репозиторий odota/dotaconstants, `build/patch.json`); 7.42 добавлен 18.11.2026 (крупный патч: нейтралки 5→4 тира, +HP героям и т.д.); до 400 про-матчей сайт показывает 7.41 с плашкой. Сайт подхватит новый патч сам. Карта вардов — `map_740.webp`; при изменении карты взять новую из odota/web `public/assets/images/dota2/map/`.
- Связки и сборки считаются SQL через `/explorer?sql=` (только про-матчи; паб-данных по связкам у OpenDota нет).
- Константы героев/предметов: `/constants/heroes`, `/constants/items`; картинки с `cdn.cloudflare.steamstatic.com`.
- Кэш ответов в localStorage на 1 час.
- Устойчивость: `fetchRetry` повторяет при 429/5xx/сетевой ошибке; константы (`getConst`) при отказе OpenDota берутся с `raw.githubusercontent.com/odota/dotaconstants/master/build/<name>.json` (CORS есть); `loadPeriod` — `Promise.allSettled`, падение одного запроса не роняет страницу; `errHint()` объясняет причину (сеть/лимит 429/таймаут 15 с/5xx). Тяжёлый `posCTE` ограничен последними 5000 матчами периода (`POS_MATCHES`).

## Важно
- Внутри inline `<script>` нельзя писать строку `</script>` даже в шаблонах — обрывает весь скрипт.
- Схема БД explorer: `sql/create_tables.sql` в odota/core. Логи (`obs_log`, `sen_log`, `obs_left_log`, `purchase_log`, `kills_log` …) — тип `json[]` (массив), а не json: разворачивать `unnest(col)`, длина — `cardinality(col)`; `::jsonb` даёт ошибку 400. Таймаут запроса explorer — 15 с.
- Код ещё не проверен на живых данных OpenDota — только на моках (Playwright). Из облачной среды Claude api.opendota.com недоступен, поэтому проверку делает пользователь в браузере.
- Dotabuff/Stratz не используются: у Dotabuff нет API, Stratz требует токен.
